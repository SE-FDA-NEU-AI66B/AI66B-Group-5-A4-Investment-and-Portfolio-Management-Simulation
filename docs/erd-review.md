## 2. Three-way agreement: ERD image vs dictionary vs SCHEMA

Checked every table, column, key and multiplicity across `docs/images/erd.png`
(generated by `scripts/diagram.py`), design.md section 2 and `database.py`.
All six tables agree, including `UQ (account_id, instrument_id)`,
`UNIQUE FK instrument_id`, dual `audit_event` FKs and the `1 - 0..1` quote
multiplicity. No missing or extra relationship was found.

## 3. Constraint test evidence

Command: `python -m pytest tests/test_erd_constraints.py -v` (each test builds
its own database in pytest `tmp_path` from `SCHEMA`; nothing committed).

Result: **26 passed in ~1s.** Full suite: **31 passed** (26 new + 5 existing
`test_market.py`). `ruff check .`: clean.

Covered: six-table inventory; UNIQUE email (case-insensitive), symbol,
holding pair and quote snapshot; FK rejection for quote/holding/trade/audit
with enforcement on; CHECKs for cash, prices, quantity, cost, role, status,
side and source; NULL realised P&L for buys; exact US05-AC1 numbers round-trip
(1000, 30000, +2000000); integer average-cost storage (6,000,000/200 = 30,000
via Decimal); partial-sale rounding stays out of storage; FK checks require
`PRAGMA foreign_keys = ON` per connection; timestamps accept any text so
ISO-8601 validation stays in service code.

## 4. Findings

- **F1 (future):** US01 lockout (5 wrong passwords, 15 minutes) has nowhere to
  live yet. Acceptable: login is deferred; record it when login is implemented.
- **F2 (by design):** `UNIQUE(instrument_id)` keeps one snapshot and erases
  tick history. Correct for BR10 "latest snapshot"; US09 time series therefore
  needs a future snapshots table, already marked backlog.
- **F3–F6 (backlog, already marked):** no rejected-order rows (US08), no
  conditional-order storage (US07/BR4), no valuation snapshots (US09/US11), no
  achievement timestamps (US12/BR8). Traceability already labels these
  deferred/backlog; the schema must not pretend otherwise.
- **F7 (service boundary):** `audit_event` cannot prove `admin_id` is an admin;
  role check plus atomic status/audit write stay in service code (BR9).
- **F8 (verified by test):** FKs need `PRAGMA foreign_keys = ON` on every
  write connection, as init-db does. Writers that skip it silently lose
  protection.
- **F9 (verified by test):** timestamp TEXT has no format CHECK; ISO-8601
  validation stays in service/adapter code.
- **F10 (needs PO decision):** money is integer VND and average cost is an
  exact division (e.g. 10,000/3 has no integer average). The service must round
  explicitly with Decimal and store the rounded remainder; rounding must never
  feed back into storage. PO still has to fix the rounding rule before trading
  is implemented.

## 5. Draft PR #60 delta (static review, not merged)

PR #60 adds nullable `instrument.reference_price_vnd` (>0) and `reference_at`,
makes `price_quote.previous_close_vnd` nullable via table rebuild, adds an
idempotent `migrate_market_data` preserving rows/IDs, a newer-only
`write_dnse_event`, and a seed/dnse CASE in the market query.

- Nullable additions are sound: existing rows read NULL, which passes CHECKs.
- The rebuild preserves PK/FK/UNIQUE/CHECKs and explicit ids; it runs inside
  init-db's transaction context.
- Newer-only predicates (`reference_at IS NULL OR <`, `source = 'seed' OR
  `quoted_at <`) match BR10; equal timestamps are correctly ignored; unknown
  symbols insert nothing (no orphans).
- Watch item: a dnse quote without a reference leaves `previous_close_vnd`
  NULL, so the page must handle a missing daily change.
- After #60 merges, re-run `tests/test_erd_constraints.py` plus a migration
  test (old seed DB with existing rows migrates without loss or ID change).

## 6. Decision: KEEP the model, no redraw

Evidence: every M2-committed storage need is covered and tested; the ERD,
dictionary and schema agree; all gaps are already and correctly marked
deferred/backlog/service-pending in traceability instead of being hidden.
Redrawing would add churn without fixing any real M2 gap, so no new ERD source,
image, dictionary or traceability changes ship in this PR.
